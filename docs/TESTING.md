# Testing

## Runner

Every test runs with Vitest (ADR 0007): `pnpm test` is `vitest run`, and `pnpm check` runs it. `vitest.config.ts` includes `src/**/*.test.ts` and `scripts/**/*.test.ts` and excludes `.scratch`, `.claude`, `.data` and `.next`. Test files import `describe` and `it` from `vitest` and assert with `node:assert/strict`.

## Where tests go

A test sits next to the file it tests, named `<file>.test.ts`: `src/core/order-matching/match-items.test.ts` tests `match-items.ts`. Repo tooling in `scripts/` is tested the same way (`scripts/check-docs.test.ts`). A table of cases shared by two tests lives in its own file next to the code it describes: `src/core/order-matching/item-line-cases.ts` lists every size and quantity text with the Item it parses to or its failure, and `item.test.ts` runs it.

## What a test checks

Test behaviour through public functions: what the Owner is asked and gets, what Carrefour and the LLM are asked, what a command prints and its exit code. Do not test how state or caches are stored.

## No live calls

Tests never call Carrefour or start a Claude Code session.

- Core use cases take their ports as arguments, so tests pass fakes of `Llm` and `OnlineStore` (see `src/core/agent-chat/resolve-item.test.ts` and `src/core/order-matching/match-items.test.ts`).
- The Carrefour adapter takes an `HttpClient`; its tests answer with recorded responses from `src/adapters/carrefour/fixtures/`, kept next to the adapter that reads them. To add one, record the real answer once and save it there as JSON; [Carrefour API](references/carrefour-api.md#fixtures) lists what each fixture records.
- The Claude Code adapter takes a `ProcessRunner`; its tests fake the process and its JSON output (`src/adapters/claude-code/claude-code-llm.test.ts`).
- What the cart simulation buys is tested through `simulateCart` with an `OnlineStore` fake in `src/core/product-selection/cart.test.ts`, checking each Item's whole result: the Candidate bought, its line with reason and Notes, or the Note of an Item not got, for promotions, discounts, a product that runs out in the whole cart and kept Items. The Selection Policy is one table of cases in `src/core/product-selection/selection.test.ts` run with both price sources, simulated through an `OnlineStore` fake and the Catalog Snapshot, so the chat and the eval set's pick are tested once.
- The Plan checks are tested in `src/core/planning/plan.test.ts` with plain data, one test per rule.
- The agent chat: `takeAgentTurn` is tested in `src/core/agent-chat/take-agent-turn.test.ts` with a fake `ChatAgent` and a list for `save` (what is saved and in what order, the last 40 messages the agent gets, the Owner's message kept when the agent fails). ## The eval set is not a test

`evals/agent.json` measures the agent: scripted Owner messages over a given Profile, Chat and past Orders, scored by code on the tool calls of each turn, how each turn ended and the products of the cart. `pnpm agent:eval` runs it on demand with real Claude Code sessions, and `pnpm agent:eval-set` validates its shape in `pnpm check`. Its pieces are tested with fakes and no live call: the validator in `src/core/agent-chat/eval-set.test.ts`, the store over the snapshot in `eval-store.test.ts`, the run of a case with a scripted `ChatAgent` in `eval-run.test.ts`, the scoring over fixed runs in `eval-score.test.ts` and the report in `src/cli/agent-eval-report.test.ts`. See [LLM](LLM.md#the-agent-eval-set).

## Data validators

`pnpm agent:eval-set` validates the committed data in `evals/` and runs in `pnpm check` after the tests.
